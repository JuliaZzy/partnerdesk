Orchestrator

PLAN 把这一轮的代理和工具一起写进 tasks。没有依赖的同一波执行。只有下一步要用上一步的结果，才填 depends_on。

只有一个代理时，由它自己回复。两项及以上，或只有工具，跑完后汇总成一次回复。计划为空才进工具循环，仍不用就直接回答。

PO Agent

po/agent.py

首先判断该PO单的 status 情况

- 若为新订单，直接走下单流程，若用户提出查看旧订单情况，先检查该订单的 status
- 单独这一项时自己回复。和其他任务一起跑时，草稿留在这边，回复由编排器写。未完成的单会留在这一轮
- PO 单最终需要客户点击 confirm 确认，agent 没有提交 PO 单的权限

LLM撰写

先写关键指标、业绩表现、库存情况、下一周期计划。各节只看自己的查询、洞察和新闻。

LLM问题与风险

读完上面四节再判断写不写。要确认才补查数据库、再算或检索，沿虚线回到上面。写在摘要前面。看不出问题就整节不写。

LLM摘要

最后写。只收已经写好的章节，包括写出来的问题与风险。

五章各 20 分。低于 85 且有实质问题就整篇改，再回到这里打分。草稿不入库。

工具 / MCP

tools/ · mcp/

写进同一份计划

kind 用 tool，name 用函数名，参数放在 input。和代理没有依赖就同一波并行。

四个原生工具

web_search · translate · exchange_rate · send_email

web_search新闻和公开网页。报表里的热点检索是另一条，不经过这里。

translate / exchange_rate翻译和汇率。translate 若等上一步，正文用上一步的结果，不在 input 里编。

send_email只有用户明确要发才排。正文用上一步的译文。不编造收件地址。

MCP

配了才并进同一份工具清单。模型填参数的方式和原生工具一样，看不到 key。

计划为空

才进工具循环，最多 4 轮。同一轮里点了多个就并行，下一轮再用上一步的结果。一个都没用，就直接回答。

工具和 MCP 与代理写在同一份计划里。会话标题 session_open 和计划并行，不调度代理。 采购单确认提交、表格收成销售事实，都在这条聊天路径之外。
